# Báo cáo rà soát kỹ thuật, Supabase, internal link và semantic SEO

Ngày rà soát: 29/07/2026  
Phạm vi: toàn bộ dự án Greenia Homes, ưu tiên không thay đổi nội dung và giao diện hiển thị hiện tại.

## 1. Cảnh báo kỹ thuật

Trạng thái trước xử lý: dự án từng có khoảng 347-348 cảnh báo kỹ thuật ở nhóm ESLint/TypeScript, chủ yếu gồm:

- `any`, `@ts-ignore`, dữ liệu snapshot chưa type rõ.
- Import icon/component không dùng.
- Hook React thiếu dependency.
- Thẻ/icon `Image` bị ESLint hiểu nhầm là ảnh thiếu `alt`.
- Dữ liệu `extraData` linh hoạt chưa có type mô tả các trường đang dùng.

Tác động nếu không xử lý:

- Dễ phát sinh lỗi runtime khi dữ liệu Supabase thiếu trường hoặc sai kiểu.
- Khó phát hiện lỗi khi build/deploy.
- Giảm độ tin cậy kỹ thuật cho PageSpeed/Accessibility/SEO vì alt ảnh và cấu trúc dữ liệu chưa rõ.
- Dễ làm lỗi SSR/ISR khi render dữ liệu từ Supabase hoặc fallback local.

Kết quả xử lý:

- ESLint toàn dự án: đạt, không còn cảnh báo.
- TypeScript typecheck: đạt.
- Build production: đạt.
- Các lỗi kết nối Supabase trong build local là do sandbox chặn mạng (`EACCES`), không làm fail build.

## 2. Firebase và Supabase

Kết luận: mã nguồn hiện không còn sử dụng Firebase SDK thật. Các file tên `firebase.ts` và `firebase-realtime.ts` chỉ là lớp tương thích API cũ, toàn bộ luồng dữ liệu thật đi qua Supabase.

Lý do dữ liệu vẫn có thể còn trong Firebase Dashboard:

- Quá trình chuyển hệ thống sang Supabase là dạng migrate/copy dữ liệu, không tự động xóa dữ liệu gốc trên Firebase.
- Firebase là hệ thống độc lập; nếu chưa chạy quy trình decommission/xóa collection cũ thì dữ liệu lịch sử vẫn nằm ở đó.
- Không nên xóa dữ liệu Firebase tự động nếu chưa có bản backup và xác nhận không còn nhu cầu đối soát.

Khuyến nghị tiếp theo:

- Giữ Firebase ở trạng thái archive ngắn hạn nếu còn cần đối chiếu.
- Sau khi backup, có thể lập kế hoạch xóa project/collection cũ thủ công trong Firebase Console.
- Không đưa lại Firebase SDK vào dependencies.

## 4. Internal link/URL system

Đã bổ sung hệ thống link nội bộ dùng chung tại `src/lib/internalLinks.ts`.

Nội dung đã chuẩn hóa:

- URL gốc `https://greeniahomes.vn`.
- Route quan trọng: trang chủ, sản phẩm, chuyển nhượng, cho thuê, căn hộ, nhà phố - biệt thự, dự án, tin tức, thị trường, liên hệ, chính sách, điều khoản.
- Sitemap dùng link graph chung và chống trùng URL.
- Layout thêm schema điều hướng chính (`ItemList`) để AI/search bot hiểu cấu trúc site tốt hơn.
- `public/llms.txt` được viết lại UTF-8, bổ sung bản đồ URL và chủ đề semantic.

Ghi chú: vẫn còn nhiều điều hướng trong UI dùng `button/onClick` vì đây là kiến trúc client routing hiện tại. Footer/Navbar và card chính đã có nhiều link thật. Nếu muốn tối ưu sâu hơn cho crawler, bước sau nên chuyển dần các button điều hướng nội bộ quan trọng thành `<a href>`/`Link` mà giữ nguyên giao diện CSS.

## 5. LSI keyword / semantic keyword

Kết luận: không nên tối ưu theo nghĩa “nhồi LSI keyword”. Hướng đúng là semantic topical coverage: dùng cụm chủ đề tự nhiên, liên quan trực tiếp đến nội dung và nhu cầu người dùng.

Đã bổ sung cụm ngữ nghĩa chính:

- Tư vấn bất động sản chuyên sâu.
- Bất động sản cao cấp TP.HCM.
- Thị trường và dự án.
- Giao dịch an toàn.

Các cụm này được dùng cho metadata/site schema và `llms.txt`, không thay đổi nội dung giao diện.

## 6. Kiểm thử đã chạy

- `npm run lint -- --format compact`: đạt.
- `npm run typecheck`: đạt.
- `npm run build`: đạt.
- `npm run verify:production`: đạt khi chạy với quyền mạng.

## 7. Kế hoạch điều chỉnh tiếp theo nếu muốn tối ưu sâu hơn

1. Chuyển dần các nút điều hướng nội bộ quan trọng thành link thật có `href`, giữ nguyên style hiện tại.
2. Bổ sung internal links theo ngữ cảnh trong nội dung bài viết/sản phẩm/dự án khi biên tập nội dung mới.
3. Theo dõi PageSpeed production sau deploy vì điểm thực tế phụ thuộc mạng, ảnh, cache, dữ liệu Supabase và CDN.
4. Nếu xác nhận Firebase không còn cần đối soát, backup rồi decommission dữ liệu Firebase cũ.
